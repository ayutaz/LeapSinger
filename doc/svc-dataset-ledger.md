### ここから読み取れる制約

**確認済み: JVS-MuSiC の 24 kHz は本プロジェクトの mel 設定と整合しません。** `mel.fmax` は
16,000 Hz、`mel.sr` は 44,100 Hz です。24 kHz 音源の Nyquist は 12 kHz なので、**12〜16 kHz の
mel bin が常に空**になります。これを混ぜて学習すると、その帯域を「無い」と学習してこもった出力に
なります。話者数 100 は魅力的ですが、そのままでは multi-singer corpus に使えません。
帯域制限を承知で低域だけに使うか、除外するかの判断が要ります。

**確認済み: GTSinger は非商用（NC）かつ継承（SA）です。** 日本語を含み 80.59 時間、技法ラベル
6 種（mixed voice / falsetto / breathy / pharyngeal / vibrato / glissando）付きで、規模と内容は
最有力です。一方 **CC BY-NC-SA は MERT を不採用にしたのと同じ理由で商用配布と衝突**します。
さらに ShareAlike が学習済みモデルの重みに及ぶかは条文から読み取れません。

**確認済み: VocalSet は CC BY 4.0 で、いま調べた中で唯一「商用利用可・帰属表示のみ」です。**
20 名 10.1 時間、技法 17 種。ただし a cappella の音階・アルペジオ・ロングトーン・抜粋が中心で、
**歌詞のある楽曲ではありません**。content encoder の学習分布としては音素の偏りが大きく、
multi-singer corpus 単独としては不足します。技法の網羅性は随一なので、**評価用や技法補強**に向きます。

**技法ラベルの副次的な価値:** GTSinger か VocalSet を使う場合、M0 ゴール 3 の「発声スタイルの
coverage」が**自動で集計できます**。現在 `preprocess/svc/coverage.py` はラベルが無いため音域しか
出せません。

**GTSinger の倫理条項（確認済み）:** README は「本人の同意なく特定個人の歌声を生成すること」を
明示的に禁じています。SVC はまさにその技術なので、**target singer の同意**が前提になります。

**帯域チェックを検査に追加しました。** GTSinger 自身が `check_valid_bandwidth.py` を同梱している
ことから分かるとおり、「宣言された sample rate より実際の帯域が狭い素材」は実在します。
`preprocess/svc/audit.py` の `effective_bandwidth_hz()` で実際の上限周波数を測り、
`AuditThresholds(min_bandwidth_hz=16000.0)` を渡すと `band_limited=...` として弾きます
（既定は無効。純音のような合成信号を誤検出しないため）。

### 実データで見つかった欠陥と修正

**確認済み:** 歌手単位でランダムに held-out を選ぶと、**性別が極端に偏りました。**

| seed | 層化なし（修正前） | 層化あり（修正後） |
|---|---|---|
| 0 | eval=男男 / test=男男 | eval=女男 / test=女男 |
| 1 | eval=男男 / test=女男 | eval=女男 / test=女男 |
| 2 | eval=女男 / test=女女 | eval=女男 / test=女男 |
| 3 | eval=女女 / test=女女 | eval=女男 / test=女男 |

SVC は異性間の変換が難所なので、held-out が片方の性別だけだと**評価がその難所を素通り**します。
`split_by_group()` に `strata` 引数を追加し、層をラウンドロビンで配ることで held-out に必ず
各層が混ざるようにしました。**素材が決まったら性別で層化して split を作ります。**

### 実音声での検査（M0 ゴール 2）

**確認済み:** リポジトリ内の実歌唱（`demo/audio/*_gt.ogg` と
`notebooks/sample_data/ritsu_flashblack_0000.wav`、3 DB 分の 17 クリップ・99.5 秒・15 曲）に
検査を通しました。全件 44.1 kHz です。

| 設定 | 受理 | 除外 | 除外理由 |
|---|---:|---:|---|
| 既定（帯域チェックなし） | 17 | **0** | — |
| `min_bandwidth_hz=16000` | 13 | **4** | すべて `band_limited`（15,668〜15,702 Hz） |

**確認済み: 弾かれた 4 件の遮断周波数は 15.67〜15.70 kHz にそろっています。** これは
**Ogg Vorbis の非可逆圧縮の痕跡**で、素材の欠陥ではなく配布形式の性質です。`mel.fmax` が
16,000 Hz なので、この素材で学習すると最上位の mel bin が常に減衰した状態になります。

**この結果の読み方（重要）:** `demo/audio/` は**デモ用に ogg へ圧縮した抜粋**であり、
元の歌声 DB そのものではありません。したがってこの reject list は
**検査が実音声で機能することの実証**であって、3 DB の素材に対する判定ではありません。
実素材で流すときは、非圧縮の原本に対して `min_bandwidth_hz=16000` で検査します。

**副次的な確認:** 帯域チェックを入れない既定設定では 17 件すべてが通りました。clipping・
無音・DC offset・長さの閾値が、実際の歌唱に対して過剰に厳しくないことの確認になります。

### VocalSet 全件（音声 3,613 件）を通した結果

**確認済み:** `VocalSet11.zip`（1,981 MB、Zenodo 1442513、CC BY 4.0）を取得し、全 3,613 wav
（**44.1 kHz / mono / PCM_16**）に検査・coverage・split を通しました。**実データが 4 つの
問題を暴いたので、順に記録します。**

| 項目 | 値 |
|---|---|
| 受理 / 除外 | **3,573 / 40**（除外はすべて `clipping`） |
| 受理時間 | **8.73 時間** |
| 歌手 | **20 名**（female1–9 / male1–11） |
| 技法 | **17 種** |

#### 問題 1: 歌手 ID をファイル名から取ると leakage する

`FULL/<歌手>/<種別>/<技法>/<file>.wav` という構造ですが、**32 件はファイル名に歌手接頭辞が
ありません**（例: `FULL/female2/arpeggios/lip_trill/lip_trill_arps.wav`）。さらに
**`male8` ディレクトリに `m9_` で始まるファイルが 1 件**あります。

ファイル名から歌手を取ると、同一人物が `female2` と `f2` の 2 つの ID に分かれ、
**held-out にしたはずの歌手が train にも入ります。** 最初の集計では歌手が 27 名に見えていました
（正しくは 20 名）。**ディレクトリ名を歌手 ID の唯一の正とします。**

#### 問題 2: 技法ラベルに表記ゆれがある

`vibrato`（255 件）と **`vibrado`（6 件）** が別ディレクトリとして存在します。コーパス側の
誤記です。正規化しないと vibrato を過小に数え、存在しない技法が 0.5% として現れます。
技法は 18 種に見えていましたが、正規化して **17 種**です。

#### 問題 3: `min_bandwidth_hz=16000` は実歌唱に対して厳しすぎる（推奨を撤回）

3 節で「実音声には `mel.fmax` と同じ 16000 を推奨」と書きましたが、**実測で否定されました。**

| 実効帯域 | p05 | p25 | p50 | p75 | p95 |
|---|---:|---:|---:|---:|---:|
| VocalSet 603 件抽出 | 10,355 | 13,456 | **15,996** | 22,026 | 22,026 Hz |

16,000 Hz で切ると **51% が落ちます**（実際 1,915 件が `band_limited` になりました）。
しかし **p75 と p95 が Nyquist（22,026 Hz）に達している**ので、このコーパスは帯域制限されて
いません。母音の伸ばしは高域が薄く、息や摩擦音は Nyquist まで届く、という**内容による差**です。

**訂正した方針:** 帯域チェックは**1 クリップの合否判定に使わない**。コーパス全体の分布で見て、
p75 / p95 が Nyquist 付近なら full-band、分布全体が特定周波数で頭打ちならその sample rate から
上げた素材、と判定します。`preprocess/svc/audit.py` の説明も修正しました。

#### 問題 4: 全長 1 回の FFT は素因数によって極端に遅い

`effective_bandwidth_hz` が信号全長で FFT を取っていたため、長さが大きな素因数を持つファイルで
処理が跳ね上がり、3,613 件で 10 分を超えました。固定長 8,192 の窓へ切って平均する方式に変え、
**4.1 分 → 0.6 分（6.6 倍）**になりました。窓を平均する分、ビンごとの暴れも減ります。

#### 技法 coverage（正規化後・受理分のみ）

straight 13.7% / slow_piano 13.3% / slow_forte 12.2% / vibrato 11.3% / vocal_fry 6.5% /
breathy 5.3% ほか。

#### 層化 split

`eval = [female9, m11]`、`test = [f7, m7]` のように**全 seed で男女が混ざる**ことを確認済みです。

### GTSinger 日本語分の実測（2026-08-30）

## 5. 配布形態ごとに何が使えるか

**決定:** **A（手元でのみ使用・配布なし）**。研究・個人利用のため、CC-NC 系も research-only も使えます。
将来 B / C へ移る場合は、下の表のとおり使える素材が大きく変わります。

| 目指す形 | 使える corpus | 制約 |
|---|---|---|
| **A. 手元でのみ使用（配布なし）** | ほぼ全部（GTSinger、VocalSet、既存 3 DB） | 研究用途の範囲。JVS-MuSiC は 24 kHz なので除外 |
| **B. 非商用で重みを配布** | GTSinger（SA の解釈を確認）、既存 3 DB（要問い合わせ） | 夏目悠李の SVC 用途確認が必須。ShareAlike の波及を確認 |
| **C. 商用配布** | **VocalSet のみ**（+ 波音リツ） | GTSinger・OpenSinger は NC で不可。VocalSet は楽曲でなく音階中心なので単独では足りない |

**確認済み: C（商用配布）を目指す場合、無償で入手できる大規模な「歌詞つき楽曲」コーパスは見つかりませんでした。**
商用可なのは VocalSet（音階中心・10.1 h）と波音リツだけです。自前収録か有償調達が要ります。
これは M0 の打ち切り条件に直結します。

### sample rate が最大の足切りになる

**確認済み:** `mel.sr` 44,100 Hz・`mel.fmax` 16,000 Hz なので、**24 kHz 音源（Nyquist 12 kHz）は
12〜16 kHz の mel bin が常に空**になります。これで学習すると、その帯域を「無い」と学習して
こもった出力になります。3 節で JVS-MuSiC を外したのと同じ理由です。

**この基準で落ちるもの:** OpenSinger（50 h・66 歌手）、JVS-MuSiC（100 歌手）、
M4Singer（流通形態が 24 kHz）。**歌手数が多い順に落ちる**のが痛い点です。

### 選定案

| 用途 | 第一候補 | 理由 |
|---|---|---|
| **multi-singer base** | **GTSinger**（80.6 h / 20 歌手 / 48 kHz） | 帯域を満たす唯一の大規模**実録音**。日本語を含む 9 言語で、技法ラベル 6 種つき |
| 同・補強 | ACE-Opencpop の 44.1 kHz 版（128.9 h / 30 歌手） | 歌手数と時間を足せる。**ただし合成音声**（下記） |
| **target singer** | 既存 3 DB のいずれか（44.1 kHz・日本語） | 日本語で 44.1 kHz の実録音はこれが現実的。規約は 1 節参照 |
| **未知 source の test set** | **VocalSet**（20 歌手・CC BY 4.0） | base と歌手が重ならない。技法 17 種で難所を突ける |

**注意（ACE 系）:** ACE-Opencpop と ACE-KiSing は、ACE Studio の仮想歌手を元音声に合わせて
チューニングして作った**合成音声**です。論文自身が "Tuning for V oice Match" として手順を
説明しています。SVC の target 音色を学ぶ素材としては、合成特有の癖を学ぶ risk があります。
**推奨:** base の中核は GTSinger（実録音）に置き、ACE 系は歌手数を増やす補強に留めます。

**日本語素材の薄さ（確認済み）:** 44.1 kHz 以上の日本語歌唱は、既存 3 DB と GTSinger の
日本語 2 名（JA-Soprano-1 / JA-Tenor-1）しかありません。計画の見積もり「20〜50 人 /
100〜300 時間」を日本語だけで満たすのは、公開素材では不可能です。**多言語の base で
音素表現を学び、日本語の target へ fine-tune する**構成が現実的です。

### これが素材選定に与える含意（重要）

**仮説:** 本パイプラインは mel を NHVSing に渡して波形にします。**NHVSing が見たことのない
歌手の mel は out-of-distribution になり得ます。** 逆に、NHVSing の学習に使われたコーパスを
base に選べば、音響モデルの出力 mel が vocoder にとって in-distribution に保たれます。

これは 6 節の選定（base = GTSinger）と**競合します**。GTSinger は NHVSing の学習に
使われていません。トレードオフは次のとおりです。

| 選択 | 利点 | 懸念 |
|---|---|---|
| **GTSinger 中心** | 80.6 h・20 歌手・48 kHz の実録音。日本語含む 9 言語、技法ラベル | NHVSing にとって未知の音色。vocoder 側の劣化リスク |
| **NHVSing 学習セット中心** | mel が vocoder に in-distribution。日本語 5 種（きりたん・夏目・リツ・くるみ・No.7） | 個々が小規模。要ログインのものが 2 件。歌手数を稼ぎにくい |

**推奨:** M2（実音声 smoke）の時点で**両方を少量ずつ試し、同じ mel を NHVSing に通して
比較**します。ここで差が出るなら、それは条件付きトラック (B)「NHVSing target fine-tune」を
起動する根拠になります（[実行計画](svc-plan.md) 7 節）。**M3 の本格学習の前に決めます。**
